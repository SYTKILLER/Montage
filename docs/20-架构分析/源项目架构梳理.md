## 1. 项目概览

Compositor 是一个 **类 Photoshop 的 macOS 图像编辑器**，面向合成（compositing）与照片后期工作流，完全开源、零第三方依赖（连 Sparkle 更新器都是唯一外部框架）。作者目标是复刻 Photoshop 的核心交互：图层/混合模式/蒙版/调整层/选区/自由变换等。

| 维度 | 事实 |
|---|---|
| 语言 | Swift（SwiftUI + AppKit）+ C（像素内核）+ 内嵌字符串形式的 Metal 着色器 |
| 规模 | ~33,000 行 Swift（217 个文件）+ ~2,300 行 C（9 个内核） |
| 工程 | 单 Xcode target，无 SwiftPM/CocoaPods 依赖，无 .metal 文件（Metal 运行时编译） |
| 图形栈 | 合成主力是 **Core Image（CIImage DAG）**；特效/笔刷/变形用 **4 组 Metal compute 内核**；CPU 侧 **Core Graphics 全功能兜底** |
| 持久化 | 自定义 `.comp` 文档包（manifest.json + PNG 资产），无 Core Data |
| 平台 API | Core Image / Metal / Core Graphics / ImageIO / Vision（对象选择、去背景）/ vImage（降采样）/ CIRAWFilter（相机 RAW） |

作者还为 AI 协作专门写了文档：`AGENTS.md`、`docs/project-format.md`（.comp 格式权威规格）、`docs/writing-comp-files.md`（教 AI 直接写 .comp 工程文件）、`docs/brush-performance.md`（笔刷性能设计笔记）、`docs/references/`（Photoshop 对照截图）。

├─────────────────────────────────────────────────────┤

│  Document/  54 文件 ~13.6k 行        ◄── 核心层      │
│  值语义数据模型 + EditorSession 编辑中枢 + 工具/撤销  │
├──────────────────────────┬──────────────────────────┤
│  Rendering/ 21+10 文件    │  IO/ 19 文件             │
│  ~7.4k 行 Swift           │  ~3.6k 行                │
│  GPU/CPU 双轨渲染管线      │  .comp 包 / PSD / 导入导出│
│  + 2.3k 行 C 像素内核      │  + 文件监视 / 应用生命周期 │
└──────────────────────────┴──────────────────────────┘
```

**依赖方向**（同一 target，靠惯例分层而非 import 强制）：

- `UI → Document`：所有控件直接绑定 `@Observable` 的 `EditorSession`，无 ViewModel、无 Environment 注入。
- `UI → Rendering`：`EditorCanvas: NSViewRepresentable` 是 Rendering 暴露给 SwiftUI 的唯一接口。
- `Document → Rendering`：会话持有 `CanvasViewport`、`LayerRenderer` 等；导出/烘焙调用 `drawLiveComposite`。
- `Document ↔ IO`：通过共享 DTO（`ProjectSnapshot`/`ProjectManifest` 等）解耦存储，但 `ProjectController`（IO）是 MainActor 的 UI 粘合层，会弹 SwiftUI sheet。
- 两处刻意的反向边：IO 的 `ProjectController` 直接呈现 UI 层的导出/网格 sheet；Rendering 的 `EditorCanvas` 调 UI 层的 `ShortcutSettings.shared`。

## 3. Document —— 数据模型与编辑逻辑（核心层）

### 3.1 一句话定性

**"结构化值世界"**：文档、图层、蒙版、选区、调整参数全是 `struct`；像素一律是不可变 `CGImage`；所有编辑 = 构造新值 + 快照入撤销栈。唯一有状态的可变对象是会话（UI 观察状态与工具草稿）和笔画引擎（瓦片缓冲）。C/Metal 内核只做纯函数式像素变换。

### 3.2 中央会话 EditorSession

- `@Observable final class`（`Document/EditorSession.swift:102`），**每个打开的项目一个实例**，约 100 个属性，是整个应用的"单一事实源"。
- 拥有：`document: CanvasDocument?`（值类型文档）、`history: DocumentHistory`（撤销）、当前工具与各工具草稿、模态编辑会话（`LevelsEdit`/`FilterEdit`/`HueSaturationEdit` 等 `@Observable` 类）、视口 `CanvasViewport`、预览缓存。
- 观察技巧：性能敏感状态标 `@ObservationIgnored`（笔画、剪贴板、缓存）；用 `brushRevision` 计数器驱动画布重绘；250ms 延迟的 `showsBusy` 防止忙碌指示闪烁。
- 并发闸门：`isProjectBusy` + `CheckedContinuation` 等待队列，所有长操作先排队；提交用乐观并发检查（`image ===` 对象标识比对）保证图层未被并发改动。
- 工具接入：**没有工具协议/基类**。`NavigationTool` 枚举 16 个 case；每个工具以 EditorSession 扩展方法实现（begin/continue/finish/cancel），配一个草稿对象；`selectTool` 统一做切换时的提交/取消。

### 3.3 撤销系统：快照（Memento），非命令模式

- `DocumentHistory`（`Document/DocumentHistory.swift:7`）保存 `Entry{before, after}` 两个完整文档快照。**值快照共享不可变 CGImage，图层编辑零像素拷贝**——这是整个撤销系统廉价的关键。
- `beginEdit/endEdit` 可嵌套事务（深度计数）；按条数（100）与独占字节（256MB）双向裁剪；`revision` UUID 跟踪"已保存"状态，支持异步保存期间的并发编辑。

### 3.4 图层模型

- `ImageLayer` struct（`Document/EditorSession.swift:4`）：字段含 `asset: ImportedImage?`（像素）、`transform: LayerTransform`、`parentID/isGroup`、`opacity/blendMode`、`mask: LayerMask?`、`maskSourceID`（剪贴蒙版）、`adjustment: LayerAdjustment?`、`shape`、`text`、`effects`。**图层种类（像素/文件夹/调整/形状/文本）靠可选项组合表达，无子类继承**。
- 层级 = **扁平数组 + parentID 邻接表**（非树），底到顶排列。文件夹是 pass-through 的：组不透明度逐层相乘，组蒙版逐层裁剪，组不做整体合成。
- 像素载体 `ImportedImage`：不可变 CGImage + 96px 缩略图 + 可选 `RasterSnapshot`（稀疏瓦片快照）。
- 绘制中的像素活在 `BrushStroke` 的 **256px 瓦片**里（只给碰到的瓦片分配可写内存），收笔提交后重新固化为不可变 CGImage。
- 剪贴蒙版：`maskSourceID` 指向下方图层；`LiveMaskGraph` 做环路校验，支持拖入自动并入剪贴组、断链、烘焙。

### 3.5 调整与滤镜

- 建模：**enum 判别 + 大参数 struct，无协议**。调整层 `AdjustmentKind` 12 种 + `LayerAdjustment` 拍平参数 struct；滤镜 `FilterKind` 18 种 + 巨型 `FilterSettings`。磁盘兼容手法：新参数一律 optional + `resolvedXXX` 计算属性兜底。
- 调整层参数存在图层上（随撤销/工程包）；滤镜不落参数，确认时一次性烤进像素；`LayerEffects`（6 种图层样式）永不改像素，由渲染层缓存绘制。
- 模态编辑类（`FilterEdit` 等）持有预览任务与降采样图；**调整层面板复用滤镜面板**：先把图层下方内容烘成采样图编辑，OK 后只把参数写回 `LayerAdjustment` 元数据，像素永不动。

### 3.6 选区与像素工具

- `DocumentSelection` = `CGPath` + 羽化，**存在文档内、随撤销**；`nil`=无选区，空 path=显式"什么都不许碰"。布尔/扩缩/羽化全在 path 层；`coverage()` 光栅化为灰度覆盖图供所有编辑裁剪。
- 选区生成工具统一产出 path：套索/选框（草稿对象）、魔棒（C 核 `wand_mask/wand_trace`）、对象选择（Vision 前景实例蒙版 + 引导滤波细化）、色彩范围（实时预览面板）。
- 像素工具共享一台"栅格编辑引擎" `BrushStroke`（class，`Document/BrushStroke.swift:121`）：瓦片化、每瓦片覆盖上下文、笔画级不透明度封顶、GPU 瓦片 coverage、克隆样本。**画笔/橡皮/修复/克隆/模糊都是它的不同配置**；涂抹/液化用独立的 `WarpStroke`（文档尺寸工作副本 + MetalWarp）。
- 像素级移动选区 = 用 BrushStroke "举起"选区像素；Cmd-T 浮动选区 = 抬到临时层用普通变换手柄编辑后融回。

### 3.7 全局约束

`DocumentLimits`（`Document/DocumentLimits.swift`）：单边 ≤30,000px、单表面 ≤200MP、文档总预算按物理内存自适应（≤800MP）、蒙版另计 1 亿像素——被 Document/IO/Rendering 三方共用。

## 4. Rendering —— GPU/CPU 双轨渲染管线

### 4.1 总体

一条**双轨管线**：优先 GPU（Core Image 负责图层栈合成 + 4 组自编译 Metal compute 内核负责笔刷/变形/特效/噪点），CPU（Core Graphics）**全功能兜底**。所有开销控制围绕三个思想：**按身份缓存 + 稀疏瓦片 + 脏区增量重绘**。

### 4.2 着色器：没有 .metal 文件

全部 Metal 源码是 Swift 字符串常量，运行时 `MTLDevice.makeLibrary(source:)` 编译（不依赖 Xcode 的 Metal 工具链）。四个编译点：

| 文件 | 内核数 | 职责 |
|---|---|---|
| `Rendering/MetalLayerEffects.swift` | 9 | 图层特效：alpha 抽取→可分离膨胀/腐蚀（描边）→可分离高斯（阴影/辉光）→环带→平移→最终合成，单 command buffer 内逐 pass `memoryBarrier` |
| `Rendering/MetalWarp.swift` | 5 | 涂抹/液化：拾取/混合携带色、**每像素偏移场**（rg32Float）前向变形——像素始终从未动原图按偏移一次重采样（仿 Photoshop 防发糊） |
| `Rendering/MetalBrushCoverage.swift` | 1 | 连续笔刷 coverage：按行进距离积分"光学密度"（8 点 Gauss–Legendre，coverage=1−exp(−density)），与指针事件频率无关 |
| `Rendering/GPUNoise.swift` | 2 | 添加杂色/胶片颗粒，哈希与 CPU 版完全一致 |

### 4.3 图层栈合成 = Core Image DAG

`GPUCanvasRenderer`（`Rendering/GPUCanvas.swift:13`，@MainActor 单例）持 `MTLDevice` + `CIContext`。每帧：CGImage 经 `replace(region:)` 直传为 `.rgba8Unorm` 纹理（蒙版 `.r8Unorm`）→ 已绘制图层用 `RasterSnapshot` 经 blit 逐瓦片拼装 → 按层序折叠出 CIImage DAG：混合模式走 CI 混合滤镜（14 种）、蒙版 `CIBlendWithRedMask`、剪贴蒙版栈 `CIBlendWithAlphaMask`、调整层 `CIColorCurves`/`CIColorCube`(33³ LUT)/CI 模糊/GPUNoise → 渲染进 `CAMetalLayer` drawable。**混合在 GPU sRGB 空间完成，与 CPU/Photoshop 观感一致**。

### 4.4 CPU 兜底（功能超集）

入口 `CanvasView.draw(_:)`（`Rendering/EditorCanvas.swift:861`）先试 GPU，失败/不支持（用户开关、快照/打印、CI DAG 遇到不支持情形）则整帧 Core Graphics 合成。关键 CPU 组件：

- `SeparableBlend.swift`：CG 画不了/画不对的混合模式（Color Burn/Dodge 软边、Linear 系列、Vivid/Pin Light、Subtract、Divide 等）用 Core Image 在 sRGB 工作空间补齐。
- `AdjustmentSurface.swift`：空间类调整（模糊/噪点）先离屏渲染一圈 halo 余量。
- `RasterSnapshot.swift`：**不可变稀疏位图**（base + 不相交 patch 列表），连续位图只在真正消费时经 `CGDataProviderDirectCallbacks` 惰性物化——**鼠标抬起绝不物化**（性能笔记：1058ms → 8.7ms 的关键）。
- ≥200% 缩放时 CPU 路径改为按导出管线 1:1 合成可见像素再最近邻放大。

另有 **9 个 C 像素内核**（`Rendering/*.c`，约 2300 行，经 Bridging Header 进入）：AdjustPixels（Camera Raw 等）、BrushPixels、HealPixels（修复）、ContentFill（内容识别填充）、DitherPixels、LensPixels、LevelsPixels、NoisePixels、WandPixels（魔棒匹配+描边）。Document 对 `CGContext.data` 裸指针直接调用。

### 4.5 缓存体系（五层，统一失效哲学）

**不做显式 invalidate——靠"绘制产生新 CGImage/新 RasterSnapshot"的身份更替让旧条目自然过期**，再由 LRU/帧时钟/内存压力回收。

| 缓存 | 内容 | 键 | 回收 |
|---|---|---|---|
| `DownsampleCache` | vImage Lanczos 严格 2× 减半链（保证瓦片对齐） | CGImage 对象身份 | LRU + 2 亿像素预算 |
| GPU 纹理缓存 | 图层/蒙版/笔刷纹理及降采样级 | (图像身份, level) | 90 帧未用逐出 + 3 秒空闲 + 内存压力分级清理 |
| `TiledPieceCache` | 已提交快照的 1024px 合成拼块 | (快照身份, level) | 快照不可变，仅 LRU + 1.5 亿像素预算 |
| `EffectsPreviewCache` | 特效预览成品图 | 图像+蒙版+变换+特效值的等价性 | 每层留 3 条（防撤销闪烁），全层共享 ~64MiB |
| 小缓存 | CI 立方 LUT、草稿文本、蒙版摆放等 | 值/身份等价 | 上限固定 |

### 4.6 画布与视口

- `EditorCanvas` 是 `NSViewRepresentable`，包 `CanvasView: NSView`（纯 AppKit，非 MTKView）；GPU 帧画在子视图 `MetalCanvasView`（CAMetalLayer），覆盖层叠加其上。
- `CanvasViewport`：纯值 struct，核心是 `pointsPerPixel = zoom / backingScale` 与文档像素↔视图点的双向映射；fit、锚点缩放、换屏保中心。
- 重绘节流：`synchronizeDisplay()` 构建 Equatable 的 `DisplayState` 快照，**diff 后局部 `setNeedsDisplay`**——笔刷只失效笔画脏矩形映射的屏幕区域。

### 4.7 覆盖层与画布内交互

全部是 `CanvasView` 的 NSView 子视图（`wantsLayer=true` 避免连带整画布重绘；`hitTest` 返回 nil 穿透事件）：像素网格线、变换/裁剪手柄+**蚂蚁线**（后台按屏幕分辨率重描+LOD 缓存）、笔刷光标（增量失效）、取色环、画布内文字编辑（NSTextView 覆盖 + "镜像"机制，画布画文字位像、编辑器只画光标）。另内联构建了大量自定义 NSCursor。

### 4.8 线程模型

**主线程是绝对中心**（CanvasView、GPU 提交、特效调度全部 MainActor，靠只上传脏瓦片控制帧时长）。仅有的后台点：特效预览专用串行队列（60ms 防抖+取消）、蚂蚁线 LOD 重描、导出等外部 worker。Metal 侧靠单 command queue 顺序 + 显式 `memoryBarrier` 保证次序。没有通用瓦片调度队列——笔刷瓦片在指针更新时同步算完。

## 5. IO —— 持久化、文件格式与导入导出

### 5.1 三层结构

1. **无 UI 的 actor 存储/编解码层**：`ProjectStore`、`ImageImporter`、`ImageExporter`、`RawImporter`、PSD 管线——围绕 `ProjectSnapshot` DTO 运转，多重校验保证"坏文件永不替换活文档"。
2. **内核级变更感知层**：`ProjectWatcher` + `ProjectDigest`——让磁盘上的 .comp 成为可被外部（AI 代理、同步盘）协作书写的"活文件"。
3. **MainActor 编排层**：`ProjectController`（每项目标签一个）+ `CompositorApplicationDelegate`——面板/表单/路由/生命周期。

### 5.2 .comp 磁盘格式（`docs/project-format.md` 权威）

```
Example.comp/                        ← macOS 文档包（目录）
├── manifest.json                    ← ≤4MiB；format/version/colorSpace/documentID/
│                                      width/height/resolution/activeLayerID/
│                                      layers[]（自底向上）/guides[]
├── images/<UUID>.png                ← 每层一个 8-bit RGBA PNG（文件名=层ID，大写）
├── images/<UUID>.mask.png           ← 灰度蒙版（白显黑隐），与层共享 transform
└── QuickLook/Preview.jpg            ← 保存时写，加载时忽略
```

- `ProjectManifest.current = 11`，`supported = 1...current`；**版本严格门控**：声明 v1–6 的文件不得含 v7+ 才有的记录（调整层/组蒙版/模糊/live mask/text runs…），校验不过整个文件被拒；新能力必须 bump 版本 + round-trip 测试。
- **变换（位置/缩放/旋转）留在 manifest 不烘进像素**——移动图层零成本、原始导入不受影响。
- 保存：`ProjectStore.save` 用 `FileWrapper` 组装整棵包 → `NSFileCoordinator(.forReplacing)` + `.atomic` 原子替换；**保存期间文档可继续编辑**（快照持数据，如 Photoshop）。加载：逐资产校验（防符号链接逃逸、manifest ≤4MiB、单资产 ≤512MiB、必须单帧 8-bit PNG、字节读进内存再解码防止 CGImage 绑定文件源）→ 校验全过才 `installProject`。
- 层记录字段：id/name/isVisible/transform/imageFile/parentID+isGroup/opacity+blendMode(25 种)/mask/maskSourceID(剪贴链 ≤256)/adjustment(12 种)/text runs/effects/maskPlacement/shape。
- 上限：边长 30,000px、源像素 1 亿（蒙版另计 1 亿）、10,000 层。

### 5.3 外部变更检测（设计亮点）

- `ProjectWatcher`：`DispatchSource.makeFileSystemObjectSource` 监听包目录/manifest/images 三路径，事件合并 300ms；因原子替换会换掉被监听 fd，每事件按路径重新 arm。
- `ProjectDigest`：SHA256(manifest 字节 + 各资产文件名与大小)——故意不读内容，"只被 touch 过"digest 不变；半写包匹配不上任何已知值。
- 流程：digest 变了才处理 → 有未保存修改且前台弹"Revert / Keep Mine"，绝不静默覆盖；忙时指数退避重查；后台标签期间挂起，回前台再问。**没有定时自动保存**，未保存状态由撤销 revision 驱动。

### 5.4 PSD 支持：纯手写只读导入

按 Adobe 官方规格原创实现（明确声明非 GPL 衍生）。支持 PSD/PSB、仅 8-bit RGB：栅格层、文件夹、蒙版（含解链/禁用/链接）、剪贴蒙版、文本（自写 EngineData 解析器，提取字体/颜色/字距，产出**可编辑**文本层）、矩形/椭圆活形状、Levels/Curves/Hue-Sat 调整层、25 种混合模式映射。智能对象/图层样式/复杂矢量/其余调整类型 → 栅格化或丢弃，并生成用户可见的转换报告（`PSDConversionSheet`）。**无 PSD 导出**。

### 5.5 图像导入导出

- `ImageImporter`（actor）：ImageIO 解码 JPEG/PNG/HEIC/TIFF(+扁平 PSD)，EXIF 方向修正，统一输出 sRGB RGBA8 + 96px 缩略图；SVG 经 NSImage 一次画入位图（不留矢量）。
- `ImageExporter`（actor）：复用渲染栈做全分辨率扁平化 → CGImageDestination 编码 PNG/JPEG（带 DPI）；QuickLook 预览 ≤1024px。
- `RawImporter`：`CIRAWFilter` 显影约 30 家相机 RAW；内嵌 actor 队列缓存 CIRAWFilter（重建 1.5s，改参近乎免费）实现滑杆实时预览。
- `ImageResizer`（Image Size：每层独立重采样）/ `CanvasResizer`（Canvas Size：只平移 origin 不动像素，可生成填色底层）。
- `RecentProjects`：`NSDocumentController` 最近列表的镜像。

## 6. UI —— SwiftUI 外壳 + AppKit 深度嵌入

### 6.1 应用骨架：单窗口多标签

- `CompositorApp`：**单 `Window`（非 WindowGroup/DocumentGroup）** + 巨型 `.commands` 菜单构建器，菜单命令经 AppDelegate 暴露的 `session`/`projects` 转发属性作用于"当前标签"。
- 多项目 = **一个窗口 + 工具栏里自绘的标签条**（非 NSWindow Tab）：每个 `ProjectTab` 封装一套 `EditorSession + ProjectController`；切标签即整体重建 ContentView；标签支持拖拽重排、未保存圆点、溢出折叠、跨标签拖图层。
- `ProjectWindowBridge`：藏在背景里的 NSViewRepresentable，代理 NSWindowDelegate 截获关闭走保存确认、回填 window 给 sheet 挂载。
- 强制深色外观、阻止 SwiftUI 乱开窗（Finder 打开走 AppDelegate）。

### 6.2 主工作区布局（`ContentView.swift` 手工组合）

```
┌──────────────────────────────────────────────────┐
│ 工具栏：项目标签条（自绘胶囊）                      │
├──────────────────────────────────────────────────┤
│ 顶部工具选项条（42pt，随工具切换）                  │
│   Move→变换检查器 / 画笔家族→笔刷控件 / 裁剪→裁剪控件…│
├───┬──────────────────────────────┬───────────────┤
│ 工 │  标尺（可选）                  │ 图层面板        │
│ 具 │  ┌──────────────────────┐    │ (可拖边调宽)    │
│ 竖 │  │  EditorCanvas 画布    │    │ · 标题条       │
│ 栏 │  │  (Metal + 覆盖层)     │    │ · 外观条(不透明 │
│56pt│  │                      │    │   度/混合模式)  │
│ +  │  └──────────────────────┘    │ · NSTableView  │
│ 色 │                              │   原生图层列表  │
│ 板 │                              │ · 底部操作条    │
├───┴──────────────────────────────┴───────────────┤

- 图层列表特意用 **NSViewRepresentable 包 NSTableView**（`NativeLayerList`）：原生鼠标按下选择/拖拽无双击延迟，细粒度 `reloadData(forRowIndexes:)` 避免缩略图重建。
- 工具竖栏装在自制的无滚动条 NSScrollView 里。

### 6.3 对话框体系：两类

1. **非模态浮动面板**（调整/滤镜）：自制可拖动 `FloatingPanelController` 承载的 NSPanel（记忆位置，关闭=取消）；Camera Raw 特殊地停靠主窗右缘。**开合由 ContentView 对 session 状态的 `.onChange` 驱动——session 状态是唯一事实源**。全部"实时预览 + Cancel/OK"，控件变更即调 `session.updateFilter/updateLevels/...`。
2. **项目级窗口 sheet**（尺寸/导出/网格）：IO 层 `ProjectController` 以 NSHostingController 呈现，@State 草稿 + 确认回调，"确认后应用"。JPEG 导出带真实压缩预览；RAW 显影 60ms 防抖实时预览；PSD 转换是纯确认列表。

### 6.4 自定义交互基建（Photoshop 手感的关键）

- `NumericScrub`：`.scrubbable()` 修饰器——标签即滑块，横向拖改值，遍布所有面板。
- `SliderSnap`：method swizzling NSSliderCell 修掉系统滑块动画（一处修复全局生效）。
- `HeldModifiers`：@Observable 单例 + 本地事件监视器实时报告修饰键（⌘ 按住时变换检查器临时反显 Auto Select）。
- `KeyboardShortcuts`：完整可自定义快捷键系统（位编码 Chord、全量清单、UserDefaults 持久化、冲突校验、按键录制器），在画布响应链边界做事件翻译。
- `ArrowStepper`：数值框聚焦时 ↑/↓ 步进（Shift ×10）。

### 6.5 曲线/色阶编辑器

两套自绘 SwiftUI `Canvas` 曲线编辑器：CurvesControls（4×4 网格 + 256 段 Hermite 插值曲线 + 锚点增删拖动，每通道 RGB/R/G/B）；Camera Raw 双页曲线（参数式 + 锚点式）。色阶面板有直方图 + 黑场/Gamma/白场三角手柄。

### 6.6 状态流

无 ViewModel、无 Environment 注入：`@Observable` 大对象 + `@Bindable` 直接绑定，视图直接写 session 属性（单向数据流不严格），但对话框生命周期由 session 状态唯一驱动。画布刷新是"推通知、拉状态"：SwiftUI 变化触发 `updateNSView` → `synchronizeDisplay()` 自行从 session 拉取。

## 7. 贯穿全局的设计模式（移植时最值得研究的部分）

1. **值语义 + 不可变像素 = 廉价撤销**。文档是 struct，历史是整文档快照；编辑生成新不可变 CGImage 整层替换；`==` 用对象标识避免像素比较。这是全项目最核心的架构决策。
2. **身份即缓存键**。从 CPU 降采样缓存到 GPU 纹理到特效预览，失效零协议成本——代价是绘制必须总是产生新图像对象。
3. **256px 瓦片是统一货币**。笔刷 coverage 瓦片（Metal）→ BrushPatch → RasterSnapshot → 拼块缓存 / GPU blit / 特效脏区，一条瓦片链路贯穿绘制、显示、提交。性能笔记实测：4K 文档笔刷更新中位 2.64ms，mouse-up 8.7ms。
4. **CPU/GPU 双轨严格对齐观感**：相同 Lanczos 圆整、相同 sRGB 混合、相同噪点哈希，切轨不跳变；GPU 不支持的情形自动落 CPU。
5. **快照式撤销 + revision UUID**：支持异步保存期间的并发编辑与"已保存"精确跟踪。
6. **坏文件永不替换活文档**：加载校验全过才 install；保存期间可继续编辑；外部变更 digest 比对后用户裁决。
7. **磁盘格式即发布契约**：版本严格门控、optional + resolved 兜底向后兼容、round-trip 测试。
8. **变换与像素分离**：位置/缩放/旋转存 manifest，像素永远是原始分辨率（非破坏变换）。
9. **平台手感靠定制**：数值拖拽、滑块吸附、修饰键跟踪、快捷键系统、原生图层列表——UI 工作量的一大块是交互基建而非布局。
