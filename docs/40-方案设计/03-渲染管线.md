# 03 渲染管线（GLES）

> 状态：✅ 已定案（2026-10-05，含用户风险排查修订 R3.1–R3.9，见 §12）。上游：[02-数据模型与编辑会话.md](./02-数据模型与编辑会话.md)（TileGrid/PixelSource/脏瓦片）。
> 本文决定：帧流程、合成 DAG 的 GLES 实现方式、混合模式着色器、纹理与缓存管理、视口坐标、覆盖层分工、帧调度。
> 已核验：`OH_NativeWindow_CreateNativeWindowFromSurfaceId`（external_window.h:759）、EGL 头齐全、GLES3 头齐全、native_image.h 存在。

## 1. 总体形态：视口空间合成 + sRGB 非线性混合

- **合成发生在视口分辨率**（屏幕像素数），不是文档分辨率——每帧成本 = 视口像素 × 图层数，与画布大小无关（与源项目 GPU 路径的 CIImage DAG 同构）。
- **混合在 sRGB 非线性空间进行**（源项目 GPUCanvas 头注释明确：与 CPU 路径、Photoshop 观感一致）——帧缓冲直接存 sRGB 编码值，不做线性化，不启用 GL_FRAMEBUFFER_SRGB。CPU 兜底路径（若有）必须用同一色彩空间，保证双轨观感一致（源项目的对齐纪律）。

## 2. 帧流程（T2 渲染线程）

```
NativeVsync 回调
  → 若无脏（无 dirtyTiles / 视口未变 / 无动画帧）→ 跳帧（不提交，省电，LTPO 允许降频）
  → 锁 docMutex 取帧快照：绘制列表（扁平化的图层序列，含 effectiveOpacity/blendMode/可见性）、
     脏瓦片集合、视口变换、preview 参数、选区轮廓多段线
  → 解锁（此后只读不可变数据）
  → 逐层合成（§4 DAG）→ 覆盖层绘制（§7）→ eglSwapBuffers
  → 清已上传的脏位；纹理 LRU 记账
```

帧率档位（Q2 LTPO 纪律）：交互中（手势/笔画）expected=120/min=90；空闲浏览 expected=60/min=0；无动画且无脏 → 停止请求帧，事件到来再恢复。蚂蚁线动画按源的 0.12s 步进相位（动画帧仅在有选区时存在）。

## 3. Surface 与 GL 上下文

1. ArkTS `XComponent(type: SURFACE)` → `OH_ArkUI_SurfaceHolder` 生命周期回调（Created/Changed/Destroyed）。
2. Created：`OH_NativeWindow_CreateNativeWindowFromSurfaceId(surfaceId)` → T2 线程 `eglGetDisplay/EGLInitialize` → 选 config（RGBA8888、RECORDABLE 按需）→ `eglCreateContext`（GLES 3.0）+ surface。**上下文只在 T2 线程 current，"谁使用谁绑定，用完即释放"**（Q4 实践要点）。
3. Changed：按新尺寸重建视口 FBO（见 §4）；Destroyed：释放 surface 与 drawable，上下文可保留待重绑。
4. **M0 需实测**：模拟器（Huawei_2in1_Foldable）的 `GL_MAX_TEXTURE_SIZE`、可用 GLES 版本串、swap 行为——登记到 01 层 M0 验证清单。

## 4. 合成 DAG：每层两趟（assemble + blend）

对扁平化绘制列表自底向上，维护一个"累积合成"FBO（acc，视口分辨率）：

```
Pass A（assemble，逐层）：
  把该层的可见瓦片画进临时层 FBO（layerTex，视口分辨率）
  - 每个可见瓦片 = 一个 textured quad（顶点=瓦片在文档空间的包围盒经视口变换）
  - 片元：采样瓦片纹理（线性过滤）；若图层带蒙版 → 同一 shader 采样蒙版瓦片并乘 alpha（D2.3 掩码即真相）
  - 蒙版与图层共享同一 transform；解链蒙版（maskPlacement）按其独立变换单独 assemble（M5）
  - 裁剪到视口：只生成与视口相交的瓦片 quad（瓦片剔除）

Pass B（blend，逐层）：
  全屏 quad，混合着色器双纹理输入（src=layerTex, dst=acc）：
  out = blendMode(src × layerOpacity, dst)   // §5 混合函数族
  写回 acc（ping-pong 双 FBO 轮换，避免自读自写）
```

- **为什么两趟**：Photoshop 混合族里非可分离模式（hue/saturation/color/luminosity）与大多数可分离模式都需要同时读 src 与 dst 做逐通道数学——固定功能 glBlendFunc 覆盖不了（GLES3 无 KHR_blend_equation_advanced 时不能 per-channel 混合方程）。两趟是 GLES 3.0 上最直白的正确实现；单趟优化（图层瓦片打入 TEXTURE_2D_ARRAY、混合 shader 内按 uv 选瓦片）列为后置优化（O3-2）。
- **文件夹组**：pass-through 语义（源项目 LayerGroups）在"扁平化"阶段解决——组内各层 effectiveOpacity *= 组不透明度、组蒙版转为对每层的额外裁剪掩码，合成时无组概念（对应源 FolderMaskClip）。
- **剪贴蒙版栈**（源 LiveMaskRenderer 语义）：base 先 assemble（alpha 置 1）→ 子层依次 blend 进 base 临时 FBO → 最终以"base 原 alpha"为掩码把结果 blend 到 acc（一次带掩码的 Pass B）。M5 细化。
- **调整层**（M6）：合成到该层位置后对 acc 跑一个全屏调整 Pass：Levels（uniform 参数）/Curves（256×1 逐通道曲线纹理，Hermite 插值 CPU 侧烘焙）/色彩类（33³ 3D LUT，GLES3 原生支持 3D 纹理）。C 内核负责烘焙 LUT，shader 只查表。
- **图层特效**（v2）：可分离膨胀/模糊 = 多 Pass ping-pong（对应源 MetalLayerEffects 的 rows/columns 分离卷积），M6 后展开。
- **实时预览**（M6）：preview 参数只影响对应 Pass 的输入（LUT/参数 uniform），天然支持滑杆逐帧。

## 5. 混合模式着色器族（03 层最大单项，对应源 SeparableBlend + GPUBlend）

**每种混合模式预编译独立着色器程序**（R3.3 定案）：共享 `blend_common.glsl` 数学函数库 + 每模式一个薄外壳，init 时从内嵌字符串编译 23 个 program，绘制前切 program（不做运行时 uniform 分支——虽然 uniform 分支严格说不是线程束发散（所有片元走同一路径），但独立 program 可让驱动做常量折叠、规避移动端 GPU 的慢路径，且与源项目"运行时编译小内核"策略同构）。

| 模式组 | 实现 | 模式 |
|---|---|---|
| 可分离（逐通道数学） | 片元纯函数 | normal, multiply, screen, overlay, darken, lighten, colorBurn, colorDodge, linearBurn, linearDodge(add), hardLight, softLight, vividLight, pinLight, hardMix, difference, exclusion, subtract, divide |
| 非可分离（Lum/Sat 几何） | 纯函数（SetLum/SetSat/ClipColor，从源 SeparableBlend.swift 移植） | hue, saturation, color, luminosity |

- 共 ~23 种（对齐源 25 种减 Dissolve/Darker/Lighter——源也映射不到，落到 normal）。
- **移植纪律**：以源 `SeparableBlend.swift` / `GPUBlend`（CI 滤镜映射）的公式为准逐条对拍，不凭记忆写（移植与对拍规范）；W3C compositing 规范可作交叉参考。
- softLight 等有标准/非标准变体的，以源实现为准（对拍优先）。

## 6. 纹理与缓存管理

- **acc FBO 格式（R3.2 定案）**：优先 **RGBA16F**（半浮点，消除多层 ping-pong 的逐级量化色带），**运行时探测 `EXT_color_buffer_float` 扩展**，不支持则回退 RGBA8888 并记录（M0 在模拟器实测扩展可用性）。代价是带宽 ×2，若实测成瓶颈再评估回退策略。层/蒙版瓦片纹理保持 RGBA8888（源数据本就是 8-bit）。
- **蒙版合成**（R3.2-b 确认）：alpha 一律在着色器里 `src.a × mask` 计算，不依赖固定功能剪裁。
- **瓦片纹理**：键 `(layerId, tileIndex, tileRevision)`，RGBA8888、`GL_CLAMP_TO_EDGE`、LINEAR 过滤。256px 瓦片远低于任何 GPU 上限。
- **驻留策略（重要，防 GPU 内存失控）**：瓦片纹理**按需上传**——只有视口相交（含 margin）的瓦片才保证驻留；LRU 预算（缺省 256MB，与 02 Limits 联动）超限逐出最久未用；`onMemoryLevel` 分级清理（warning 保当前帧、critical 全清）。这样 100MP 画布不会全量进 GPU（全量=400MB）。
- **上传**：`glTexSubImage2D`（初次 `glTexImage2D`），数据源 `PixelSource::mapCpu()`；脏瓦片整片上传（256KB/片，带宽可控）；PBO 异步上传列为优化项。
- **缩小采样（fit 全景视图）**：M1/M2 直接 LINEAR 采样原图瓦片——**已知妥协：显著缩小时会有轻微摩尔纹/闪烁**（无 mip 链）。源的严格 2× 减半链（vImage，瓦片对齐避免接缝）列为 M2.1 改进项：GPU 侧按"相邻瓦片参与平均"的规则生成降采样级（halo 读取，同 02 §3 跨瓦片原则），逐级对齐。登记开放点 O3-1。
- **放大采样（≥200%）**：切换 NEAREST（对应源 crispZoom），消除模糊。
- **棋盘格透明底**：程序化片元着色器直接画（不生成纹理）。

## 7. 覆盖层分工（GL vs ArkTS）

| 内容 | 画在哪 | 理由 |
|---|---|---|
| 棋盘格、图层像素、合成结果、效果预览 | GL（T2） | 像素真相 |
| 蚂蚁线、变换/裁剪手柄、参考线、网格、画布外阴影边框、笔刷光标圆圈 | **ArkTS Stack 覆盖层**（XComponent 上叠 Canvas 2D，hitTest 透明，手势绑在宿主——PixLume 三层结构范式） | 几何交互 UI 用 ArkTS 画最快，且与手柄命中检测同源；蚂蚁线用 lineDashOffset 动画 |
| 画布内文字编辑光标/选区 | ArkTS（源项目同构：画布画位像，编辑器画光标） | M9 |

注意：笔刷光标的"克隆预览/软边"类像素级效果（源 BrushCursorOverlay）延后到 M3 按需评估是否下沉 GL。

## 8. CPU 轨的边界（R3.7–R3.8 澄清）

"初版不做 CPU 合成兜底"**仅指实时屏幕渲染不做双轨**（工作量×2，GL 不可用按致命错误处理）。但 **CPU 导出合成器是必需组件**：导出要全功能扁平化（混合模式/蒙版/调整层在 CPU 上重算，对应源 ImageExporter.render 管线）——混合数学函数以纯 C/C++ 写一份，GLSL 版本从同一公式移植，两者共享"数学规格"。

- **双轨视觉回归测试（R3.7 采纳）**：构造覆盖 23 种混合模式 × 典型图层的测试工程，GPU 渲染与 CPU 导出逐像素对比，容差 ΔE < 1；纳入 M2.1 起的常规测试。
- **色彩管理（R3.8 定案）**：全管线固定 **sRGB 非线性**（合成、导出、标签一致；源项目 manifest colorSpace 也是固定 "sRGB"——平级）；Display P3 留后续版本。CPU 导出不做色彩空间转换（同空间直出），只保证 8-bit 编码语义一致。
- **GL 上下文丢失恢复（R3.9 采纳，架构天然支持）**：检测上下文丢失（makeCurrent 失败/GL 错误）→ 全部 GL 缓存（瓦片纹理/acc FBO/program）标记失效重建。**引擎文档在 C++ 侧，天然不受影响**；GPU 状态在本架构中本来就是"身份键控的纯派生缓存"（01/02 层不变量），恢复 = 清缓存 + 按需重上传，无需序列化恢复流程。
