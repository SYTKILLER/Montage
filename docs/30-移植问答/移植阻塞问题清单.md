## P0 — 渲染架构（技术路线选型）

### Q1. 高频重绘自绘画布的推荐渲染路径
图像编辑器画布需要 60fps 级别的逐帧重绘（图层合成结果 + 进行中的笔刷），并支持像素级读取/写入。请比较以下路径在鸿蒙 PC（API 24）上的官方支持度、性能与推荐度：
1. **ArkUI Canvas 2D**（CanvasRenderingContext2D + drawImage/PixelMap）——是否 GPU 加速？能否承担"每帧重绘整幅图层栈"的负载？
2. **Native XComponent + OpenGL ES**（EGL + GLES 3.0，NAPI 侧自绘）；
3. **Vulkan**——API 24 是否支持？鸿蒙 PC 设备（MateBook 等的 GPU）是否保证 Vulkan 硬件支持？
4. **OH_Drawing（NDK 2D 绘图库）**——是否 GPU 加速？适合这种场景吗？
官方对"图像编辑器类高频自绘场景"的推荐架构是什么？

### Q2. 渲染循环与垂直同步
选定渲染路径后，如何驱动与屏幕刷新同步的渲染循环（等价 macOS CVDisplayLink / MTKView 的 draw 回调）？Native XComponent 场景下帧回调由什么驱动（`OH_NativeXComponent` 回调？`NativeVsync`？自建线程 + eglSwapInterval？），官方推荐的帧调度模型是什么？

### Q3. 像素数据高效上屏（零拷贝/低拷贝路径）
编辑器的图层像素是 CPU 侧的位图缓冲（会频繁被笔刷局部更新）。请问：
- CPU 侧 `PixelMap` / `ArrayBuffer` 如何高效送入 GPU 纹理（Native XComponent + GLES 场景下的 `OH_NativeImage` / `EGLImage` / `NativeWindow` buffer 复用等路径）？
- 笔刷每次只更新局部 256×256 瓦片，如何只上传脏区（纹理子区域更新）？
- 反向：GPU 合成结果如何高效读回 CPU（导出场景），有没有 PBO/异步读回的推荐做法？

### Q4. GPU 图像合成与滤镜能力
图层栈合成需要：逐层 25 种混合模式（multiply/overlay/soft-light/color-dodge/linear-burn/subtract/divide 等 Photoshop 全集）、蒙版混合（按灰度 mask 混合两层）、非平凡模糊（高斯/运动模糊，作用在图层变换后的空间域）、曲线/色阶（可用 3D LUT 表达）、逐层透明度。请问：
- 系统是否有 GPU 图像合成/效果框架能覆盖（Image Kit 的 `imageEffect`（效果处理链）？`EffectKit`？其他）？各能力的作用范围（只作用于单张图？能否做多层 DAG 合成？）与 API 24 可用性？
- `imageEffect` 能否自定义滤镜（注入自己的 shader/kernel）？
- 若系统框架不覆盖，官方是否建议业务自写 GLSL/Vulkan shader？混合模式/蒙版合成属于常见需求，有没有官方示例工程？

### Q5. C/C++ 像素内核复用与多线程
源码有约 2300 行纯 C 像素算法内核（曲线、色阶、魔棒、修复画笔、内容识别填充等，输入输出为内存中的像素 buffer，无平台依赖）。请确认：
- 通过 NAPI + CMake 把这些 C 代码编译进 HAP、在真机/PC 上运行，是完全支持的常规做法吧？有官方示例（native 模块 + 图像处理）吗？
- 重活应放在哪里跑：TaskPool/Worker（JS 线程池）还是 native 侧自建线程（pthread + `napi_threadsafe_function` 回传结果）？大规模像素处理（上亿像素）官方推荐哪种？
- native 侧能否直接拿到 `PixelMap` 的内存指针做原地处理（`OH_PixelmapNative` / native image kit 的读写锁语义）？

## P1 — 图像处理核心能力

### Q6. 超大画布的支持上限
工程要支持最大 30000×30000 像素画布、单表面 2 亿像素、文档总像素预算 8 亿（分多层）。请问：
- `createPixelMap` / `OH_PixelmapNative` 的单图尺寸与内存上限是多少？
- ImageSource 解码时是否支持**区域解码（decode region）**与**降采样解码（desiredSize）**，用于超大图的分块（tile）加载？
- 应用进程内存上限与内存压力通知 API（等价 macOS `os_proc_available_memory` / memory warning），用于自适应缓存预算。

### Q7. 相机 RAW 解码（CIRAWFilter 等价物）
macOS 侧用 `CIRAWFilter` 显影约 30 家相机的 RAW 格式（CR3/NEF/ARW/DNG...）。鸿蒙 API 24 是否有系统级 RAW 解码/显影能力（Image Kit 是否支持 RAW 容器解码）？若无，官方对"应用内 RAW 支持"的建议路径是什么？

### Q8. AI 抠图/主体分割
两个功能依赖视觉模型：①"对象选择"（点击识别画面中的前景物体生成选区，macOS 用 Vision 的前景实例蒙版）；②"移除背景"（一键抠出主体）。Core Vision Kit 在 API 24 提供哪些相关能力（主体分割 subject segmentation？实例级分割？）？输入分辨率上限、是否需要订阅/签约、能否离线运行？

### Q9. 文字工具的排版能力
文本图层需要：系统字体枚举与自定义字体加载（等价 CoreText + `CTFontManager`）、按属性 run（字体/字号/颜色逐段不同）做测量与排版、绘制到自绘画布（不是 UI 组件）。请问：
- API 24 上自定义字体加载 API（`font.registerFont`？native 侧 OH_Drawing 字体管理？）；
- 在 Canvas/自绘 surface 上做富文本测量+排版+绘制的推荐路径（Canvas `measureText`/`fillText` 是否支持逐 run 样式？`@ohos.graphics.text`（Paragraph 绘制）能不能画进自绘 surface？）；
- 能否枚举系统已装字体列表？

## P1 — PC 桌面形态 UI

### Q10. 应用内非模态浮动面板
macOS 版用可拖动的非模态浮动 NSPanel 承载"曲线/色阶/滤镜"等工具面板（悬浮在画布上，实时预览，可关闭/可停靠）。鸿蒙 PC（自由窗口）下等价做法是什么？
- `window.createWindow` 的 SUB_WINDOW 子窗口能否覆盖在同一应用主窗口上方、跟随主窗口移动？自由窗口形态下子窗口的行为与限制？
- 还是推荐应用内 Stack 覆盖层 + 自绘拖拽（不做真窗口）？官方对"工具面板"类交互的推荐范式？

### Q11. 菜单栏集成
桌面应用的"文件/编辑/图像/图层/滤镜"菜单体系：鸿蒙 PC 自由窗口应用是否有系统级菜单栏（窗口标题栏里的菜单）可注册？若有，API 是什么（API 24 可用性）？若没有，官方推荐如何在 PC 上组织命令入口（标题栏按钮 + 下拉 Menu？右键 `bindContextMenu`？）。

### Q12. 全局键盘快捷键与焦点
编辑器重度依赖快捷键（工具切换 B/V/L、⌘Z 撤销、空格临时抓手等），且要求可自定义。请问：
- API 24 上给应用窗口注册全局按键处理（含 Ctrl/Shift/Alt 修饰组合）的标准方式（`onKeyPreIme`？`UIExtension`？native key event？）；
- 焦点管理最佳实践：画布作为"按键接收者"与 TextInput 输入态之间的切换（编辑器要求按 Enter/Esc 把焦点还给画布）；
- PC 上能否监听修饰键的按住状态（不按键也响应，等价 macOS `NSEvent.modifierFlags`）？

### Q13. 鼠标/数位板交互细节
画布交互需要：
- **自定义鼠标光标**（画笔圆圈/十字/角度光标——macOS 用自定义 NSCursor）：API 24 支持设置自定义光标吗（`cursorStyle`？`window.setWindowCursor`？自定义图片光标？）
- **滚轮缩放**（Cmd+滚轮 或纯滚轮）：自绘组件如何接收滚轮事件？API 名？
- **压感笔**：PointerEvent 是否提供 pressure/tilt？鸿蒙 PC 触控笔在自由窗口应用的透过率？
- **鼠标右键 + hover**：`onMouse`/`onHover` 语义确认。
